# Харнесс для openJiuwen Challenge: решение и оптимизация токенов

Харнесс автоматически решает пачку задач (математика, анализ `sales.csv`, поиск по базе знаний `kb/`, кодинг с тестами) в рамках ограниченного бюджета токенов. Принцип: **не звать LLM там, где ответ можно получить детерминированно, а где звать, делать это дёшево и коротко.**

## 1. Сборка и запуск

### Docker

```bash
docker build -t hack:latest .

docker run --rm \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  hack:latest \
  python /app/run_agent.py --tasks-dir /data/tasks
```

Образ собирается из `python:3.11` по `requirements.txt` (`openjiuwen==0.1.19`, `requests`). Внутрь копируются `run_agent.py` и папка `harness/`.

### Локально (например, в PyCharm)

1. `pip install -r requirements.txt` в виртуальном окружении.
2. Файл `.env` в корне проекта:
   ```
   LLM_BASE_URL=https://<адрес>/v1
   LLM_API_KEY=<ключ>
   ```
3. Запуск: `python run_agent.py --tasks-dir tasks --workers 2`. Рабочая папка должна быть корнем проекта.

### Результат запуска

- `answer.txt` пишется рядом с `task.json` сразу после решения задачи;
- `solutions.json` перезаписывается атомарно после каждого засчитанного ответа (путь по умолчанию `<tasks-dir>/solutions.json`, меняется через `OUT`);
- в конце печатается строка `done. solved=… unsolvable=… spent=…/BUDGET`. Задачи, на которых агент не справился (`miss`/`error` в логе), в обе цифры не входят.

При загрузке задач **старые `answer.txt` удаляются**, поэтому ответы прошлого запуска не могут быть приняты за новые.

## 2. Как устроено решение

```
задачи → planner → fastpath → agent (LLM) → store
          │           │           │
          │           │           └─ ReAct-цикл, короткие ответы, повтор на сильной модели
          │           └─ шаблонные задачи решаются кодом, 0 токенов
          └─ отсев невыполнимых, сортировка по выгоде, контроль бюджета
```

| Слой | Файл | Что делает |
|---|---|---|
| planner | `harness/planner.py` | находит заведомо невыполнимые задачи, оценивает стоимость, сортирует по выгоде |
| fastpath | `harness/fastpath.py` | решает шаблонные math / data_analysis / search задачи кодом, без LLM |
| agent | `harness/agent.py` | ReAct-цикл с инструментами (`python_exec`, `bash`, `write_file`, `finish`, `unsolvable`) |
| store | `harness/store.py` | запись `answer.txt` и `solutions.json` |
| llm | `harness/llm.py` | вызовы модели и учёт бюджета |

### Fastpath: 0 токенов на шаблонные задачи

| Тип | Что делает |
|---|---|
| **math** | цепочка операций над складом (поставки, умножение, деление на части, проценты); проценты считаются точной целочисленной арифметикой |
| **data_analysis** | сумма по `sales.csv`; определяет разделитель (`,` `;` таб), применяет фильтр по региону |
| **search** | «человек → работодатель → город», «в каком году родился/основан» по `kb/*.md` |

**Правило безопасности: при любом сомнении fastpath молчит и отдаёт задачу LLM.** Неверный ответ «бесплатно» хуже потраченных токенов. Он отступает, если:

- вопрос не про итоговое количество («сколько отгружено», «что было до последней операции»);
- в условии есть незнакомое предложение;
- в базе два однофамильца, документ написан прозой, есть нестандартные ключи, устаревшая заметка или алиас (`aka`);
- процент даёт нецелый результат (правило округления неизвестно).

### Agent: дёшево там, где LLM нужен

- Короткий системный промпт и жёсткие лимиты: `max_steps` 5 (первая попытка) и 6 (повтор), `max_tokens` 550 и 750 на шаг.
- Один вызов `python_exec`, напечатавший только целое число, сразу принимается как ответ без лишнего обращения к модели; `384.0` нормализуется в `384`.
- Основная работа идёт на дешёвой модели (`MODEL_CHEAP`), повтор на сильной (`MODEL_STRONG`) только для ценных задач (`reward >= RETRY_MIN_REWARD`) и если бюджета хватает с запасом.
- **Кодинг:** ответ принимается, только если тесты проходят, а файлы тестов не изменены. Ответ не засчитывается, если тесты «пройдены» через хак (`__eq__`, `sys.exit` и т.п.).

## 3. Оценка расхода токенов

Расход оценивается и контролируется на трёх уровнях.

**1. Предварительная оценка стоимости задачи** (`PRIOR_COST` в `planner.py`, в единицах бюджета):

| Тип задачи | Оценка |
|---|---|
| math | 250 |
| data_analysis | 350 |
| search | 400 |
| coding | 850 |

Выгода задачи: `reward / стоимость`. Очередь сортируется по убыванию выгоды, поэтому при нехватке бюджета теряются самые невыгодные задачи. Задачи, решённые fastpath, в бюджет не попадают.

**2. Ограничения на задачу** (`run_agent.py`):

- потолок расхода на одну задачу: `cap = 2.5 × оценка` (повтор на сильной модели: `cap × 1.3`);
- задача пропускается, если остаток бюджета меньше `0.4 × оценка`;
- повтор на сильной модели запускается, только если остаток больше `2 × оценка`.

**3. Фактический учёт** (`Budget` в `llm.py`): после каждого вызова модели списывается

```
стоимость = входные_токены / 10 + выходные_токены
```

Рассуждения (reasoning) добавляются к выходным, если прокси вернул их отдельным полем; кеш не вычитается. Когда остаток падает ниже резерва, выбрасывается `BudgetExhausted` и новые задачи не стартуют. Всё уже решённое остаётся записанным в `answer.txt` и `solutions.json`.

Лимит берётся из переменной окружения **`BUDGET`** (запасной вариант `TOKEN_BUDGET`, параметр `--budget`; по умолчанию 100000). Значение из окружения организаторов имеет приоритет над `.env`.

Итог последнего тестового прогона на 100 задачах: потрачено около 24.6k из 100k.

## 4. Поиск невыполнимых задач

Для невыполнимой задачи правильный исход: **ответа нет** (`answer.txt` не пишется). Каждая такая задача, найденная до обращения к LLM, экономит токены. Поиск идёт в три этапа.

**Этап 1. Planner** (`suspicion_score` в `planner.py`, срабатывает до всего остального). Задача невыполнима, если:

- пустое условие или `reward <= 0`;
- условие требует «живых» данных или похода в интернет: `fetch / download / open / visit / browse … <ссылка>`, текущая погода, цена, курс, новости, биржевая цена, «cannot be determined»;
- в условии упомянут файл (`.csv .tsv .json .md .txt .py .db …`), которого нет в рабочей папке;
- нет файлов нужного типа: у `coding` нет `.py`, у `search` нет документов, у `data_analysis` нет файла данных.

Шаблоны сделаны узкими, чтобы не давать ложных срабатываний: слова «current stock», «today's stock» или безобидная ссылка-подпись невыполнимыми не считаются.

**Этап 2. Fastpath** (0 токенов) распознаёт невыполнимость по содержимому данных:

- деление на ноль в цепочке операций;
- запрошенный продукт, регион или колонка отсутствуют в `sales.csv`;
- человека, работодателя, поле (`headquarters`, `born`, `founded`) нет в базе знаний;
- тесты противоречат друг другу (`double(3) == 6` и `double(3) == 7`), определяется статически по AST без LLM.

**Этап 3. LLM** может сам вызвать инструмент `unsolvable(reason)`; пустой ответ или `UNSOLVABLE/IMPOSSIBLE/NONE/N/A` тоже считается признанием невыполнимости.

Если данных недостаточно для уверенного вывода (проза, алиасы, двусмысленность), задача **не** объявляется невыполнимой, а уходит к LLM.

## 5. Собранные траектории

Траектории работы агента сохраняются в JSON-файлы для разбора и отладки.

Включение:

```bash
SAVE_TRAJ=1 TRAJ_DIR=./trajectories python run_agent.py --tasks-dir tasks
```

В Docker папку нужно смонтировать, иначе файлы пропадут вместе с контейнером (по умолчанию пишется в `/tmp/trajectories`, а `/tmp` в запуске это `tmpfs`):

```bash
docker run --rm ... -e SAVE_TRAJ=1 -e TRAJ_DIR=/traj -v "$PWD/trajectories:/traj" ...
```

- **Файл:** `<TRAJ_DIR>/<task_id>_<model>.json`. Повтор на сильной модели пишется отдельным файлом.
- **Содержимое:**
  ```json
  {
    "task_id": "math_0016",
    "model": "qwen3.6-35b-a3b-noreason",
    "framework": "openJiuwen",
    "status": "SOLVED",
    "spent_tokens": 612.0,
    "answer": "110",
    "messages": [ ... ]
  }
  ```
  `status` бывает `SOLVED` или `UNSOLVABLE`; `messages` содержит весь диалог: сообщения модели, вызовы инструментов и их результаты.
- Задачи, решённые fastpath, траекторий не имеют (LLM не вызывался).

## 6. Параметры

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | доступ к LLM (обязательно) | — |
| `BUDGET` / `TOKEN_BUDGET` | бюджет токенов | 100000 |
| `TASKS` | папка с задачами (или `--tasks-dir`) | — |
| `OUT` | путь к `solutions.json` | `<tasks-dir>/solutions.json` |
| `MODEL_CHEAP` | модель основной попытки | `qwen3.6-35b-a3b-noreason` |
| `MODEL_STRONG` | модель для повтора | `qwen3.8-27b-noreason` |
| `WORKERS` | число потоков (`--workers`); при ошибках 429 уменьшайте до 2 | 5 |
| `TIME_LIMIT_S` | лимит времени | — |
| `FASTPATH` | `0` отключает fastpath | включён |
| `SAVE_TRAJ`, `TRAJ_DIR` | сохранение траекторий | выключено, `/tmp/trajectories` |
